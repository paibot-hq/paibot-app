# AI・データサイエンス問題集の計画

> 2026年11月14日作成。DS検定（リテラシーレベル）・G検定・E資格の試験範囲を参考に、AI・データサイエンスの問題集を作る計画。仕組み（単元 → 学習項目 → 練習セット、生成 → 機械の検算 → 別モデルの盲検レビュー → 公開、教科書の本文）は数学問題集（[math-units.md](math-units.md)、`CLAUDE.md` の "Math project"）に合わせる。数学側のコード・挙動は変更しない。
>
> **2026年11月14日: 第1段階を実装**（`src/tools/ai-ds/`、`/ai-ds`）。カタログは全14単元、問題は第1段階の5単元（統計と確率・情報理論・機械学習の基礎・モデルの評価・ニューラルネットワーク）に各項目1セット（5問）。アプリの一覧にはまだ載せず、検索にも出さない。問題はデータベースではなく `src/tools/ai-ds/data/<unit>.json` に置き、問題文・解説は日本語（画面の文言は3言語）。

## 1. 目的と方針

- データサイエンス・機械学習・深層学習・AI の社会実装について、4択の問題と教科書の本文を作る。対象は、DS検定（リテラシーレベル）・G検定・E資格の受験者と、それと同じ範囲を学びたい人。
- 3つの試験の範囲は大きく重なるので、**試験ごとに分けず、共通のカタログを1つ作る**。各学習項目に「どの試験の範囲か」（`exams`）を付ける。数学の各項目に学年と数検の級を付けているのと同じ考え方。
- 問題は**オリジナル**で作る。過去問・公式例題・市販問題集の問題文や選択肢は使わない。
- 試験名は各団体の商標（「DS検定」はデータサイエンティスト協会、「G検定」「E資格」は日本ディープラーニング協会）。公式と誤解されないよう、表記は「○○の試験範囲を参考にした」までにし、「公式」「準拠」「対応」は使わない。ツール名にも試験名は入れない。
- 公開の条件は数学と同じく「機械の検算（できるものだけ）と、書き手と別のモデルの盲検レビューがOK」。運営者の確認は待たない。

## 3. 分類とID

数学と同じ「単元 → 学習項目 → 練習セット」の3階層。ID形式も数学に合わせる（単元・項目は英小文字、問題は単元＋3桁の通し番号）。

- 各学習項目に `exams`（`ds`・`g`・`e` のうち当てはまるもの）を持たせる。一覧とテストは試験で絞り込めるようにする（数学の学年・数検の級の絞り込みと同じ）。
- 試験との対応は**本サイトの目安**であり、公式の出題範囲そのものではない。シラバスの項目名と照らし合わせた結果として扱う。
- `tier`（項目の中での難しさ。1 基礎・2 標準・3 応用）は数学と同じ意味で持つ。E資格だけで問われる深さの内容は、同じ項目の tier 3 にするか、別の項目に分ける。
- 確かめ方（§4）は項目ごとに決める: **計算**（Python で答えを計算し直せる）と**知識**（盲検レビューだけ）。

## 4. 問題の形と確かめ方

| 確かめ方 | 問題の例 | 機械の検算 | 盲検レビュー |
| --- | --- | --- | --- |
| 計算 | 分散・標準偏差、ベイズの定理、エントロピー・交差エントロピー、混同行列からF値、畳み込みの出力サイズ・パラメータ数、勾配の計算、ソフトマックス | `scripts/verify_ds.py`（新規）が NumPy / SymPy で答えを計算し直し、正しい選択肢がちょうど1つかを確かめる | 問題文・選択肢・解説を確かめる |
| SQL | 表と SQL 文を見せて結果を選ぶ、目的に合う SQL 文を選ぶ | 小さな表を SQLite に入れて SQL を実際に実行し、結果を比べる | 同上 |
| 知識 | 用語の意味、手法の使い分け、歴史、法律・倫理 | なし | 正解がちょうど1つか、ほかの選択肢が確かに誤りかを、書き手と別のモデルが答えを伏せて解いて確かめる |

- 計算の問題は数学の `formula` と同じ考え方（隠した式・数値から答えを出し、見せる文と検算が同じものから作られる）。数学の式の文法で書けるものは数学の仕組みをそのまま使い、書けないもの（行列の畳み込み、表の集計など）は `verify_ds.py` に種類を足す。
- 知識の問題は数学の `statement`（文章の4択）と同じ形にする。
- **法律・倫理・ガイドライン**の問題は、解説に出典（法令名と条、ガイドラインの名前と版）を必ず書く。法改正やガイドラインの改訂で古くなるので、項目ごとに「確かめた日」を持ち、試験範囲の見直し（§6）と一緒に確かめ直す。
- 教科書の本文（数学の `math:lessons` と同じ形）も各項目に付ける。計算の例題は検算し、文章の説明は盲検レビューで確かめる。

## 6. 進め方

1. **第1段階（計算で確かめられる共通の核）**: 統計と確率・情報理論・機械学習の基礎・モデルの評価・ニューラルネットワーク（5.1・5.3・5.6・5.7・5.8）。3つの試験すべてに効き、答えを機械で確かめられる。`verify_ds.py` と、カタログ・ページの仕組みをここで作る。
2. **第2段階**: 線形代数と微分・CNN／RNN／Transformer・データの準備・SQL（5.2・5.9・5.4・5.5）。SQL の検算（SQLite で実行）をここで足す。
3. **第3段階（知識が中心）**: 深層学習の応用・AI の歴史・社会実装・ビジネス（5.10〜5.12・5.14）。
4. **第4段階（出典が要る）**: 法律と倫理（5.13）。出典と確かめた日を持つ仕組みを先に作る。
5. 試験範囲の見直し: 新しいシラバス・スキルチェックリストが出たら、§2 の版を更新し、カタログとの対応を見直す。
