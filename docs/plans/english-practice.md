# 英語問題集(`/english`)の計画

> 2026年10月25日作成。数学問題集(`/math`、[math-units.md](math-units.md)・[problemset.md](problemset.md))の仕組みを土台に、英検5級〜1級レベルの英語問題集を作る計画。**すべて計画段階であり、未実装。** 数学側のコード・挙動は変更しない。数学の仕組みの記述は `CLAUDE.md` の "Math project" に合わせている。

## 1. 目的と方針

- 英検5級〜1級(5級・4級・3級・準2級・2級・準1級・1級の7段階)レベルの、4択の英語問題集を作る。カタログは最初から7段階すべてを持ち、問題は5級から順に作る。
- 画面の作り(セット選択、4択クイズ、単元・項目ページ、テスト)、生成 → 検証 → 盲検レビュー → 取り込み、という流れは数学に合わせる。公開は複数のAIの盲検レビューがすべてOKのときに行い、運営者の確認を待たない(§5)。保存先とコードは英語用に別に持ち、数学の挙動に影響させない(§3)。
- 問題は**オリジナル**で作る。過去問・市販問題集の問題文や選択肢は使わない。
- 「英検」は日本英語検定協会の登録商標。公式の問題と誤解されないよう、表記は「英検○級レベル」までにする(「準拠」「公式」「対応」は使わない)。ツール名にも「英検」は入れない。
- 初期の対象は**文法・語彙**(短文の空所補充を4択で)。長文読解、リスニング、英作文、面接、発音は対象外。
- 公開は検証済みの問題がある項目から段階的に行う。未検証は `published: false` のまま。

### なぜ英語か

- 英検の受験者は年間約440万〜450万人(2024年度、民間記事の数字)で、検討した分野のなかで需要が最も大きい。
- 5級〜3級(中学英語)は、運営者が公開後の抜き取り確認で正誤を判断できる。
- 競合(公式サイト、学習アプリ、学習サイト)が多く、機械による答えの検算ができない、という弱みがある。そのため検証(§5)を重くする。

## 2. 分類とID

数学と同じ「単元 → 学習項目 → 練習セット」の3階層。ID形式も数学に合わせる。

| 階層 | ID形式 | 例 |
| --- | --- | --- |
| 単元 | 英小文字 | `grammar`, `vocab` |
| 学習項目 | 単元内で一意の英小文字 | `be-verb`, `present-perfect` |
| 練習セット | 学習項目内の番号 | `1`, `2` |
| 問題 | 単元+3桁の通し番号 | `grammar-001` |

- URL は `/english/<unit>/<item>/<set>`。表示順はカタログの並びで決め、IDは変えない。
- 数学の「学年(`grade`)」に当たるのが**級**。値は `e5`, `e4`, `e3`, `ep2`, `e2`, `ep1`, `e1`(準2級は `ep2`、準1級は `ep1`)。カタログの各項目に級を1つ持たせ、取り込み時に各問題へ写す。複数の級にまたがる項目は、数学と同じく級ごとに分ける(例: `comparison` と `comparison-advanced`)。
- 級の割り当ては**本サイトの目安**であり、公式の出題範囲ではない。公表情報と照合できたものは根拠を記録し、それ以外は目安と明記する。
- `tier`(その項目・級の中での難しさ。1 基礎・2 標準・3 応用)は数学と同じ意味で持つ。

### 学習項目(案)

級の割り当ては目安。実装時にカタログとして確定する。

| 級 | 文法(`grammar`) | 語彙(`vocab`) |
| --- | --- | --- |
| 5級 | be動詞、一般動詞(現在)、名詞の複数形、代名詞、疑問詞、命令文、can、現在進行形、前置詞(場所・時) | 身の回りの名詞、基本動詞、基本形容詞、数・曜日・月 |
| 4級 | 過去形、過去進行形、未来表現(will・be going to)、助動詞(must・have to・may・should)、比較(-er・-est)、不定詞(基本)、動名詞(基本)、接続詞(when・if・because)、there is | 日常の動詞・名詞、基本の熟語 |
| 3級 | 現在完了、受動態、不定詞(応用)、関係代名詞(主格・目的格)、分詞の形容詞用法、間接疑問、比較(応用)、付加疑問 | 日常・学校の語彙、熟語 |
| 準2級 | 関係副詞、関係代名詞 what、現在完了進行形、過去完了、仮定法過去、分詞構文(基本)、使役・知覚動詞 | 日常・社会の語彙、句動詞 |
| 2級 | 仮定法過去完了、仮定法の応用(I wish・as if・without)、分詞構文(応用)、強調構文、倒置(基本)、無生物主語 | 社会・科学の語彙、句動詞 |
| 準1級 | 倒置・省略・同格、動詞の語法 | 高度な語彙、多義の句動詞 |
| 1級 | (文法単独の項目は持たない) | 高度な語彙、句動詞 |

準1級・1級は、実際の試験でも語彙・熟語の比重が大きいため、語彙を中心にする。

## 3. 保存先とコード

- **問題**: `english_problems` を新しく作る。列は `math_problems` と同じ形(`id`, `unit`, `item`, `set_id`, `position`, `published`, `answer_index`, `payload`, `grade`, `tier`, `reviewed_at`)。数学の一覧(`getPlayableSets`)やテスト(`getTestCandidates`)はテーブル内の全問題を対象にしているため、同じテーブルに混ぜない。
- **成績**: 数学の匿名集計(`math_set_results`)と同じ形の `english_set_results` を作る。ログインした人の個人記録は、ログインして使う人がほぼいないため、当面は作らない。
- **置き場所**: `src/tools/english/` にまとめる("Adding a tool" の決まりどおり)。数学が `src/routes/`・`src/lib/` にあるのは古い特例。
- **画面**: 数学の `math-set-quiz.tsx` は、途中再開・完了の記録・パンくずなど `math-` 系に依存している。最初は英語側に薄いクイズ画面を作り、共通化は両方が動いてから検討する。
- **名前**: 「英語問題集」/ "English Practice" / "英语题库"。`src/lib/app-catalog.ts`・`APP_ICONS`・`messages/*.json` 3言語に登録する。UIは3言語、問題文・選択肢は英語、解説は日本語のみで始める。

## 4. 問題の形

4択の短文空所補充のみ。

```json
{
  "stem": "She ___ to school every day.",
  "choices": ["go", "goes", "going", "gone"],
  "explanation": { "ja": "主語が三人称単数で、毎日の習慣を表す現在形なので、動詞に s をつけます。" },
  "point": { "ja": "三単現の s" }
}
```

- 正答は `answer_index` 列。`choices` の並びは生成時に偏らないよう入れ替える。
- 語彙の問題も同じ形にする(例: `I usually ___ breakfast at seven.` / `eat`, `drink`, `sleep`, `play`)。
- 並べ替え・入力式は作らない。

## 5. 生成と検証

数学は SymPy が答えを独立に再計算するが、英語には**機械で正誤を決める手段がない**。そのため、独立した確認を重ねる。

```text
Claude が問題・選択肢・解説を生成(学習項目・級・tier を指定したプロンプト)
  → 形式検証(スキーマ、選択肢4つ、重複なし、正答の位置の偏り、長さ上限。scripts/validate-english.mjs)
  → 盲検レビュー(生成とは別の2つのモデル、例: Codex と Antigravity が、それぞれ独立に答えと解説を伏せて解く)
      ・正解と一致するか
      ・他の選択肢が文として成り立たないか(1つずつ判定させる)
      ・級に合わない語彙・構文がないか
      ・解説が正しいか(答えを見せたあとで判定)
  → 2つのレビューがすべてOKなら published: true
  → english_problems へ取り込み
  → 公開後、運営者が抜き取りで確認
```

- **公開の条件は、生成と別の2つのモデルによる盲検レビューの全項目OK**。全級で同じ条件にする。運営者の確認は公開の条件にしない。
- **「正解が1つだけ」の確認が最重要**。英語は文脈によって複数の選択肢が成り立ちうるため、盲検レビューで誤答の選択肢を1つずつ判定させる。
- どちらかのレビューが不一致・保留にしたものは公開しない。作り直すか、捨てる。
- 2つのモデルが同じ誤りをすることはありうる。公開後の見直しで補う。
  - 運営者が抜き取りで確認する(特に新しい項目の最初のセット)。
  - `english_set_results` で、正答率が極端に低い・高いセットを見直す。
  - 誤りを報告できるリンクを、問題の画面に後で足す。
  - 誤りが見つかったら `published: false` に戻し、同じ項目の他の問題も見直す。
- 語彙の級の目安は、当面プロンプトの指示と盲検レビューの判定で見る。公式の語彙表は確認できていないため、機械的な照合は使える資料が見つかってから足す。
- 承認は版に紐付け、問題文・選択肢・正答・解説を変えたら再検証する。内容ハッシュで再投入時の重複を防ぐ。
- 生成・検証の記録(日時、担当、条件、レビュー結果)を残す。

## 6. 画面とルート

数学に合わせる。

- `/english`: 単元の一覧。級での絞り込み、項目の検索。
- `/english/<unit>`、`/english/<unit>/<item>`、`/english/<unit>/<item>/<set>`: 単元・項目・5問4択クイズ。項目ページには、学ぶ内容と要点の短い説明を載せる。
- `/english/test/<id>`: 級別の模擬テスト(各項目から引く。毎回引き直し、保存しない・インデックスしない)。級の問題が十分にたまってから。
- 準備中のページは noindex にし、sitemap に載せない。公開する項目ページは `src/lib/seo.ts` に登録する。
