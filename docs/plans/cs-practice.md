# コンピュータサイエンス問題集の計画

> 2026年11月14日作成。IT パスポート・基本情報技術者・応用情報技術者の各試験のシラバスと、大学の情報系の標準カリキュラム（情報処理学会 J17 コンピュータ科学領域）を参考にして、コンピュータサイエンスの問題集を作る計画です。仕組みは AI・データサイエンス問題集（`docs/plans/ai-ds-practice.md`、`/ai-ds`）と同じにします。流れは、単元 → 学習項目 → 練習セット、項目ページは解説 → 例題 → 練習の順です。作るときは、生成 → 機械で検算 → 別のモデルが答えを伏せてレビュー → 公開、と進めます。

## 1. 目的と方針

- 範囲は、基本情報技術者試験の範囲を軸にします。各項目には、どの試験の範囲か（IT パスポート・基本情報・応用情報）と、大学の必修範囲かどうかを印で付けます。試験ごとに問題集を分けず、カタログは1つにします。どの印でも絞り込めるようにします。
- 試験と大学の範囲は、半分以上が重なっています（離散数学、アルゴリズム、アーキテクチャ、OS、ネットワーク、データベース、セキュリティ）。そのため、問題は重ねて作らずに共有し、印だけを変えます。
- 大学の範囲だけにある単元も入れます（計算理論、言語処理系、証明など）。逆に、試験だけにある経営・法務などのストラテジ系は最後に回します。
- 答えを機械で確かめられる問題を中心にします。AI・DS では、計算できる問題は式で答えを計算し直しました。こちらではそれに加えて、プログラムを実際に動かしたり、SQL を実行したり、オートマトンを動かしたりして答えを確かめます。知識の問題は、AI・DS と同じく答えを伏せたレビューだけで確かめます。
- 試験名の使い方は AI・DS と同じにします。「○○の試験範囲を参考にした」までにとどめ、「公式」「準拠」「対応」とは書きません。各試験の過去問題は使わず、問題はすべて自分で作ります。
- 解説・例題・問題は日本語で書きます。画面の文言は3言語にします。

## 3. 分類とID

- URL は `/cs/<unit>/<item>/<set>` にします（AI・DS の `/ai-ds/...` と同じ形）。単元と項目の ID は英小文字です。
- 項目ごとの属性は次の3つです。
  - `exams`: `ip` / `fe` / `ap` / `univ` のどれか（複数可）
  - `check`: 確かめ方（§4）
  - `fe-b`: 基本情報の科目B（擬似言語のアルゴリズム問題）の形で出すかどうか
- 練習セットは5問で、tier は 1, 1, 2, 2, 3 にします（AI・DS と同じ）。

## 4. 問題の形と確かめ方

| 印 | 確かめ方 | 中身 |
| --- | --- | --- |
| 計 | 式で計算し直す | `verify_ds.py` と同じ仕組みに、情報系の関数を足す（基数変換、補数、浮動小数点、稼働率、平均アクセス時間、MIPS・CPI、伝送時間、サブネット、EVM、損益分岐点など） |
| 実 | プログラムを動かす | 問題に擬似言語のプログラムを載せ、それを実際に実行して、出力・変数の値・呼び出し回数を答えと照らし合わせる（下の「擬似言語」を参照） |
| S | SQL を実行する | SQLite に表を作って問題の SQL を実行し、結果を照らし合わせる。AI・DS の第2段階（`dataeng`）と同じ仕組みを使う |
| 動 | 機械を動かす | 有限オートマトン・正規表現・文法などを実際に動かし、受理する／しない、生成できる／できない、を照らし合わせる |
| 知 | 答えを伏せたレビュー | 用語・概念・判断の問題。codex が答えを伏せて解き、作者の答えと合うか、問題がないかを確かめる |

**擬似言語**: 基本情報の科目Bと応用情報では、IPA が決めた擬似言語の書き方（別紙2）でアルゴリズムが出題されます。この書き方のプログラムを動かす小さな解釈器（`scripts/pseudo.py`）を作ります。そうすれば、画面に表示するプログラムそのものを実行して答えを確かめられます。Python に書き直してから動かす方法もありますが、その場合は書き直しの誤りを見逃すおそれがあります。画面では、等幅フォントで行番号を付けて表示します。

レビュー役（codex）は、答えを伏せたまま、問題文と擬似言語だけを読んで解きます。機械の検算と、別のモデルが解いた答えの両方が合った問題だけを公開します。

## 5. 学習項目（案）

- 確かめ方: §4 の **計・実・S・動・知**。
- 実装するときに、カタログとして確定します。

## 6. 進め方

1. **第1段階（機械で確かめられる核）**: 離散数学・データ構造・アルゴリズム・プログラミング・コンピュータの構成（§5.1〜5.4・5.6）。どの試験にも大学にも効く範囲で、ほとんどを計算かプログラムの実行で確かめられます。この段階で、擬似言語の解釈器（`scripts/pseudo.py`）と、擬似言語を表示する部品を作ります。
2. **第2段階**: OS・システム・データベース・ネットワーク・計算の理論（§5.5・5.7〜5.10）。SQL を実行する仕組み（AI・DS と共有）と、オートマトンを動かす仕組みを作ります。
3. **第3段階**: セキュリティ・ソフトウェア開発・情報の表現（§5.11〜5.13）。
4. **第4段階**: マネジメント・ストラテジ（§5.14・5.15）。法律は出典と確認日の仕組みを作ってから扱います。

各段階で、項目ごとに解説・例題（`lessons.json`）と、練習1セット（5問）を作ります。

## 7. 実装の形

- AI・DS 問題集（`src/tools/ai-ds/`）と同じ作りにします。ただし、2つ目を作る前に、共通の部分を `src/components/` か `src/lib/` に移します。共通にするのは、カタログの型、項目ページ、練習の画面、解説の表示、試験の印による絞り込みです。同じように、生成スクリプトとレビュー（`scripts/lib/ai-ds-models.mjs` など）も、問題集の種類によらず使えるようにします。
- そのため、AI・DS 問題集のブランチ（`ai-ds`）を main に入れてから始めます。

## 8. 決めていないこと

- アプリの名前と URL（仮に「コンピュータサイエンス問題集」、`/cs`）。アプリ一覧にいつ載せるか。
- AI・DS と同じく、練習の記録・続きから・シェアを付けるか（付けるなら問題を D1 に移す）。
- 基本情報の模擬試験（科目A・科目B）のような、試験別のテストを作るか。
- 大学の範囲で、選択（（大））の単元をどこまで入れるか（コンパイラ、並列計算、グラフィックスなど）。
