| 学習項目 | `単元.項目` | `arith.add-sub` |

### 共通の仕組み

- 画面: `src/components/math-set-picker.tsx`(セット選択)と `math-set-quiz.tsx`(4択・5問・結果)。単元ごとのルートは問題データを表示用に変換するだけ。
- データ: 原本は `src/data/math-*.json`、配信は共通の D1 テーブル `math_problems`。単元・セット・公開状態・表示順は共通列、単元固有の内容は JSON の `payload` に格納し、型は `src/lib/math-arith.ts`・`math-factorization.ts` で定義する。
- 読み出し: `src/lib/math-problems.server.ts` の `getMathSet(unit, setId)` が公開済みの問題を表示順に返す。ルートは payload を従来の表示用に変換し、成績は引き続き `math_attempts` に保存する。
- 取り込み: `npm run math:import:local|dev|prod`。共通の `scripts/import-math.mjs` が各単元の検算モジュールの bank を読み込み、共通列と payload に変換して upsert する。単元追加時は検算・payload 型・表示の変換と取り込み対象の登録を追加し、テーブル・マイグレーション・サーバー処理・CI 手順の追加は不要。
- 生成と検証:

```text
Antigravity(agy -p)が問題を生成
  → 検算スクリプト(npm run check:math-*)が答えを独立に再計算し、セットの条件を確認
  → Codex(codex exec)が答えと内部の式を伏せた状態で解き、正解と照合・問題文をレビュー
  → 人が確認して published: true
  → D1 へ取り込み
```

- 検算スクリプトは生成側の答えを信用しない。四則演算は自前のパーサーで式を評価し、因数分解は全選択肢を展開して、正解がちょうど1つであることを確認する。

## 2. 分類の考え方

**「単元 → 学習項目 → 5問セット」の3階層にする。**

- 単元: 一次方程式、分数など。URL `/math/<unit>` に対応する。
- 学習項目: 単元の中の技能。例: 一次方程式なら「移項の基本」「かっこを含む」「分数係数」「文章から立式」。
- 5問セット: 学習項目の1回分の練習。1学習項目に練習A・Bを用意し、初見のセットでも解けるかを確かめられるようにする。

「係数が10以下か20以下か」のような違いは、学習項目ではなく生成条件(難易度)として扱う。

4択では「証明を書く」「自分で立式する」「作図する」といった技能は確認できない。これらは誤りの指摘や次の一手の選択として出題できても、その技能を習得したとは扱わない。

## 4. 作る順番

前提知識のつながりを優先し、ツールの導入順では決めない。

| --- | --- | --- |
| 1 | 小数・分数、約数と倍数(約分・通分) | Node の厳密な有理数計算(`BigInt`) |
| 2 | 文字式の基本 → 一次方程式 → 連立方程式。割合・比の基本を並行 | 多項式の係数比較 |

利用者層はまだ決まっていないため、まず「四則演算から中学代数までの学び直し」を一続きに完成させる。小学生から大学生まで薄く広げるより、入口と次に進む単元がはっきりする。

## 5. 検算のルール

全単元に共通する前提: **全選択肢を調べ、正解がちょうど1つであることを確認する。** 正解の候補が成り立つことと、問題全体が正しいことは別である。

| 対象 | ルール |
| --- | --- |
| 整数 | 中間計算も安全な範囲かを確認する。範囲を超えうる単元では `BigInt` を使う。 |
| 小数・分数 | 小数は文字列から「整数+桁数」に変換し、有理数として計算する。浮動小数点で計算してから丸める方式は使わない。 |
| 方程式 | 答えを代入するだけでは解の取りこぼしを見逃す。一次は係数ゼロ、連立は行列式、二次は判別式を確認し、独立に求めた解集合と比べる。定義域・除外値も明示する。 |
| 文字式・展開 | 数点を代入して一致しても恒等式の保証にはならない。多項式に限定し、係数比較で厳密に判定する。 |
| 平方根 | `a√b` の `b` は平方因子を含まない正の整数に正規化し、係数・符号・ゼロの書き方を統一する。和は単一の `a√b` にならない点、`√(x²) = |x|` に注意する。最初は数値の根号に限定する。 |
| 近似値 | 丸め方と桁数を問題に明示する。丸めた後に選択肢が重ならないこと、真の値が丸めの境界をまたがないことを確認する。 |
| 確率・割合 | 分数の計算が正しくても、文章のモデル化は間違えうる。等確率か、戻すか戻さないか、順序を区別するか、割合の基準量は何かを明示する。小規模な確率は全列挙で独立に検算する。 |
| 微積分・極限 | CAS の結果にも定義域と仮定が必要。不定積分は積分定数と区間、定積分は特異点と収束を確認する。 |

### 文章題の盲検レビュー

Codex には答えだけでなく、内部の式と解説も伏せ、**公開される問題文だけから立式して解いてもらう。** 生成した文章と式が同じ誤解を共有している場合、式を再計算するだけでは見つけられないため。(四則演算の文章題ではすでにこの方式で実施した。)

### 見た目で正解がわかる問題を防ぐ

- 誤答は乱数で作らず、符号のミス、分配法則の適用漏れ、分母どうしの足し算など、具体的な誤概念から作る。
- 正解だけが既約分数、単位付き、長い、桁数が違う、といった書式の手がかりをなくす。
- 数学的に同じ値の選択肢(`1/2` と `2/4` など)を正規化して排除する。
- 正解の位置の偏りを、問題群全体で監査する。

符号や概算で選択肢を絞り込むのは正当な数学の技能なので、これを封じる必要はない。

## 6. 3言語とカリキュラム

- 共通の数学的分類と、国・地域ごとの課程の対応表を分けて持つ([problemset.md](problemset.md) の方針を維持)。日本語=日本、英語=米国、簡体字=中国本土、のように言語と課程を結びつけない。例えば米国の Common Core では中学段階で統計・確率を扱う。
- 自然数に0を含むか、`log` の底、度数法か弧度法か、実数解か複素数解か、丸め方を問題ごとに明示する。
- 「以上/より大きい」「少なくとも/ちょうど」「戻して引く/戻さない」など、答えが変わる条件を各言語で照合する。
- 「20%引き」と中国語の「八折」のように、翻訳で数値表現まで変わるものに注意する。
- 計算の難しさと読解の難しさを分ける。初等の問題は短文にし、通貨・人名・生活習慣への依存を減らす(現行の生成指示でもお金の話は避けている)。
- 共通データの検算に加え、**各言語の問題文だけから同じ数学的条件を復元できるか**をレビューする。

## 7. 既存単元の宿題

- **因数分解の「発展編」:** 数の範囲が広がっただけで、技能としては発展していない。共通因数、完全平方、x² の係数が1でない式を学習項目として追加する。
- **もう一度:** 同じ問題が同じ順番で出るため、2回目の満点には暗記の効果が混ざる。練習A・Bの用意、または出題順のシャッフルを検討する。
- **レビューの記録:** `reviewedAt` は日付の形式を確認しているだけで、レビューした内容と結びついていない。[problemset.md](problemset.md) にあるとおり、問題の内容ハッシュとレビュー結果を紐付け、問題文・選択肢・翻訳を変えたら再レビューが必要になるようにする。
- **`/math` のトップ:** 単元が増えると縦に並んだリンクでは探しにくい。学年段階ごとの見出しで分け、前提となる単元から次の単元を案内できるようにする。

## 9. 問題を追加する手順

1. `npm run math:generate -- arith add-sub-a --dry-run` で追加予定を確認する。単元は `arith`・`signed`・`factorization`、問題数は `--count N`（既定5）で指定できる。
2. `npm run math:generate -- arith add-sub-a` で生成する。Antigravity CLI (`agy`) が一時ディレクトリで生成し、同じ単元の既存問題を渡して重複を避ける。ID とセット内 position は最大値の続き、`published: false`、`reviewedAt` は生成日で追加される。`reviewedAt` だけではレビュー済みを保証しない。
3. 検算は生成コマンドが自動実行する。失敗時は原本を復元し、生成結果を `.math-work/` に残す。dry-run は一時ファイル上で原本と追加問題を合わせて検算する。手動では `npm run check:math-arith`（signed も含む）、`npm run check:math-factorization`。
4. `npm run math:review -- arith add-sub-a` で Codex CLI (`codex exec`) に盲検レビューを依頼する。setId を省略すると単元の全問題が対象。文章題の内部式と正解情報は渡さない。一致/不一致・文章から立てた式・指摘事項を表で確認し、`.math-work/review-<unit>-<日時>.json` の記録を読む。不一致・指摘ありは終了コード1。修正後は検算とレビューを再実行する。
5. 人が問題・3言語・選択肢・レビュー結果を確認して `published: true` にする。
6. `npm run math:import:local` で取り込み、ローカル画面で確認する。
7. 問題原本と必要な変更をコミットする。`.math-work/` は Git 管理対象外。

事前に `agy` と `codex` が PATH 上で使え、認証済みであることが必要。両CLIは stdin を閉じ、一時ディレクトリで実行する。生成・レビューの指示文は `scripts/math-prompts/` に保存している。

新しいセットを足す場合は `src/lib/math-<unit>-sets.ts` のセット一覧と3言語の翻訳を追加する。`rule` は生成条件と検算条件を指す。同条件の練習Bなら練習Aと同じ `rule` を使える。新条件なら検算スクリプトの条件表と `scripts/math-prompts/<rule>.md` も追加する。既存セットへの追加時は position の続きを使うため、文章題ミックスの奇数/偶数の条件も継続する。
