# D1 migrations

Wrangler applies the SQL files in this directory and tracks their filenames in
`d1_migrations`. Drizzle Kit generates future SQL and schema snapshots in `meta/`.
Commit both SQL and metadata. Never modify a migration that has already shipped.

All migrations, including the initial CREATE TABLE, are generated by Drizzle Kit.
When adopting Drizzle, the local and dev favorites table and migration history
were reset once to replace the former handwritten initial migration. This is not
a reset procedure to repeat: subsequent changes must use incremental migrations.
Databases that still have the old `0001_create_favorites_table.sql` history need
an explicit migration-history reconciliation or an approved reset before applying
this new initial migration.

Migrations use timestamp prefixes to preserve execution order.
Edit `src/db/schema.ts`, run `npm run db:generate -- --name descriptive_name`,
review the SQL (especially destructive changes), and apply using
`npm run db:migrate:local` or `npm run db:migrate:dev` as appropriate.
Do not use Drizzle's migration runner or `push`: Wrangler is the sole applier.
