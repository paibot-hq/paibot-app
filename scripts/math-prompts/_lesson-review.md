次は数学の練習サイトの学習項目ページに載せる「教科書の本文」（日本語 ja・英語 en・中国語 zh）。学習者が正しいと信じて読むものなので、公開してよいかを厳しく確かめる。

確かめること:
- 数学的な誤り。定義・公式・説明・例題の解説（note）・間違いの説明が正しいか。条件の抜け（「〜のときだけ」）や、言い過ぎ（いつも成り立つわけではないことを「必ず」と書く）も誤りとする。
- 説明と式の食い違い。文章中の数値・例と、formulas・examples・mistakes の式が合っているか。
- 内容の範囲が学年（{{grade}}）に合っているか。まだ習わない概念を先取りしていないか、説明が飛躍していないか。ただし、文体は学年によらず高校教科書レベルの簡潔な「です・ます」体で統一する方針なので、文章がやさしくないことは指摘しない。
- 本文が学習項目の「項目」と「練習問題の例」の範囲に合っているか。別の内容（例: 2桁×1桁と2桁×2桁）を説明していないか。
- 統計・確率・推論・分布の項目では、例題が計算式だけでなく、具体的な状況・問い・結論を含む文章題になっているか。
- kind は value・factor・solve・reason のいずれかだけを使う。新しい kind を提案しない。計算例は value でよく、prompt に文章題を置き question・steps で検算する形もよい。
- 3言語で内容・数値が同じか。各言語として自然か、用語がその言語で一般的か。
- 学習者を誤解させる表現、分かりにくい説明。
- 公式・手順の列挙だけになっていないか。量や関係の意味が示され、具体例から「なぜその操作で求められるか」をたどれるか。結論を言い換えただけの説明、暗記への誘導だけで理由を省いた箇所は修正を求める。
- 指摘は「本文」（sections・examples・mistakes・figures）についてだけ書く。「学習項目」の要点・説明・練習問題は参考情報で、そこへの指摘は書かない（本文を直しても解決しないため）。

例題と間違いの式そのもの（question・steps・wrong・right）は別の仕組みで検算済み。式を読むための書き方: * は掛け算、^ は累乗、"a = b = c" は等しい式の連なり、"x = 3, x = -3" は2つの解。
ただし kind が "reason" の例題・間違いは文章による証明や推論であり、SymPy では検証されていない。prompt の条件から reasoning の各段階と note の結論が正しく導かれるかを、あなたが厳しく確認する。reason の mistakes は wrong が誤った主張、right が条件に合う正しい主張であり、単なる計算式に置き換える必要はない。
単なる計算例を reason にして検算を避けていないかも確認する。計算すべき項目には計算例を、証明・論理・概念の判断を扱う項目には実際の推論を載せる。
examples の prompt は式の前に表示する問題文。style が "box" の例題・間違いでは、検算用データの x は画面上ですべて □ と表示する（x を学習者に見せるわけではない）。prompt・note の $\\square$ と対応しているかを確認する。

図（figures・figure）: 学習者が見る図を文章にしたものが各図の reading に書いてある（図そのものは見えない）。次を確かめる。
- caption と本文・例題の説明が、reading（図の数値・ラベル）と合っているか。図の数値が本文の数値と食い違っていないか。
- 図の中に、説明に必要な情報（長さ・角・点の座標・曲線の名前）が足りているか。図の読み方を caption や本文が誤って説明していないか。
- 図の形（座標の範囲、曲線の向き、領域のぬり方）が、説明する数学と合っているか。
